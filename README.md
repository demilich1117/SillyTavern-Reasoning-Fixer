# SillyTavern Reasoning Fixer

前端扩展，找回误入思考栏的正文，并隔离思考中的 HTML / Markdown。面向 SillyTavern 和 TauriTavern，不需要服务端插件。

## 日常使用

打开 **Reasoning Fixer · 思考修复**：

1. **自动找回正文**：生成结束后，把思考栏中指定起始标签之后的内容移回正文，并保存聊天。
2. **保护思考显示**：隔离思考中的 HTML、样式和反引号，不改写消息原文。
3. **正文起始标签**：填写预设使用的标签，默认 `content`。多个标签用逗号隔开，输入 `<content>` 也会自动整理。
4. **修复当前聊天**：手动检查当前聊天的历史消息并保存修复；关闭自动修复后仍可手动使用。

两个功能可以同时开启，也可分别使用。设置自动保存。高级设置默认折叠，包含显示方式、多档案、预设绑定、历史自动修复和调试日志。

## 找回正文的规则

例如思考栏中的内容：

```text
先分析剧情，输出时使用 `<content>` 标签……
<content>正式正文</content>
```

只把 `<content>正式正文</content>` 移入正文；讨论标签的文字仍留在思考栏。

- 默认跳过行内代码、完整/未闭合代码围栏、HTML 注释及反斜杠转义的标签，避免切断代码示例。
- 从第一个有效配置标签开始整体移动到思考末尾。同名起始标签多次出现时，沿用原有规则，取该标签最后一次有效出现的位置。内部 MVU 等标签整体保留。
- 规则依赖明确的输出格式：无代码标记的普通标签讨论仍可能被识别为正文；同名标签不应作为正文内部的嵌套起点。
- 正文开头完整的 `<think>`、`<thinking>`、`<reasoning>`、`<analysis>` 包裹也可拆回原生思考栏；未闭合的思考包裹不自动拆分。
- 生成中只保护显示，不持久化修复。生成结束或停止后按已收到的内容修复；正文起始标签之后的末尾内容可以是不完整的输出，不补齐标签。
- 默认不提取围栏里的正文。若模型总把正式正文放在代码块中，可在高级标签选项允许提取末尾完整代码块：围栏内容必须以配置标签开头，且后面没有其他文字。
- 不处理用户、系统和工具结果。同步可用 swipe；TT 未加载的冷 swipe 保持原状，加载/切换后再修复。
- 更新同内容的显示镜像，移除已失效的翻译显示缓存和思考签名，保留无关元数据。重复执行不重复追加。

## 显示保护的规则

默认以纯文本显示思考。高级设置可选择基础 Markdown，保留加粗、列表、代码等排版；HTML 仍按文字显示，不执行样式或嵌入内容。

- **原生思考栏**：单独格式化思考内容。
- **混在正文开头的思考包裹**：显示成独立折叠区，后面的正文继续使用宿主正则与 Markdown。边界未闭合时展开显示“思考边界未闭合 · 原文”，不擅自划分正文。

只识别消息开头的上述四种思考标签，不猜测无标记的自然语言思考。原生思考栏保留宿主折叠偏好。正文仍由宿主和已有正文插件负责。

## 高级规则

通常无需创建档案。多种输出格式才需要“多套规则与标签选项”：

- 当前聊天手动选择优先于预设绑定，最后使用默认档案。
- 首页标签输入框修改当前生效档案；多档案时显示正在修改的档案名。
- 编辑另一档案不会自动切换聊天；选择档案或绑定预设后生效。
- 可控制大小写、外层正文标签的保留与逐个标签选项。内部标签不因此被剥离。
- 保留旧档案、绑定、独立开关及未知字段；原先无实际作用的“允许嵌套”控件已移除。

## 安装

在宿主扩展安装界面填写仓库地址：

```text
https://github.com/demilich1117/SillyTavern-Reasoning-Fixer
```

本地开发安装只需复制 `manifest.json`、`index.js`、`style.css`、`src/`、`README.md` 和 `LICENSE` 到宿主第三方扩展目录下的 `SillyTavern-Reasoning-Fixer/`。不需要 `node_modules`、测试文件或构建步骤。TT 使用其扩展安装流程/数据目录，不按 Node 服务端部署。

已安装的用户可在宿主扩展管理中检查更新；更新后刷新页面，载入新版本。

## 兼容性与测试

源码核对目标为 ST 1.19.0、TT 2.3.0（ST 1.18.0 兼容层）。ST 使用格式化钩子；TT 使用运行期 Markdown / Reasoning 适配和内容刷新，不修改核心文件。

49 项自动化测试和两套宿主格式化函数的浏览器测试通过。**尚未在完整 ST 实例或 TT 原生 WebView 验收**；版本、方法和限制见 [兼容性记录](docs/compatibility.md)。

Node.js 20+：

```sh
npm ci
npm test
node tests/browser/server.mjs
```

浏览器测试页：`http://127.0.0.1:18764/?host=st` 或 `?host=tt`。完整验收步骤见 [测试用例](docs/test-cases.md)。
